# HandpickerStudio

複数のComfyUI環境で生成した画像を、Checkpointごとに閲覧・整理するWindowsアプリです。

## 起動

Windows 11 x64 と **.NET 10 Windows Desktop Runtime（x64）** が必要です。Microsoftの公式ページで「.NET Desktop Runtime」のWindows x64を選んでください。 [Microsoft公式の .NET 10 ダウンロード](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)

配布物はFramework-dependentのポータブルZIPです。.NETランタイムは同梱されません。書き込み可能なフォルダにZIPを展開し、`HandpickerStudio.exe` を起動してください。アプリ本体は標準ユーザー権限で利用できます。

## 画像を閲覧する

1. **登録**からプロジェクト名とComfyUIフォルダーを指定します。ポータブル版の `ComfyUI_windows_portable` と、その中の `ComfyUI` 本体のどちらも選べます。標準フォルダーと `extra_model_paths.yaml` のCheckpoint参照先を確認し、検出したHandpickerSuiteの評価JSONと連携情報を表示します。手動で登録する場合は、**手動設定・キャッシュ保存先** を開きます。
2. **参照ルート**で画像のOutputを選びます。Archiveが空欄なら、Outputと同じ階層に `_archive` を付けたパスが入ります。Archiveは変更できます。保存後、有効なルートのOutputに接続できると、Archive配下にプロジェクト・ルートごとの保存先を作成します。ルートはカードから有効・無効を切り替えられます。
   同じプロジェクトでOutput同士、またはOutputとArchive・cacheが同じフォルダーや親子関係を指す場合、ジャンクションや自分のPCのSMB共有など、実体を確認できた別名のパスでも該当箇所を表示して保存を止めます。保存後に重複が判明した場合は、該当ルートの画像走査とArchive化・解除を保留します。別プロジェクトから同じOutputを参照できます。
3. 評価別の一覧でCheckpointを選択します。画像は **一覧**、**タイル**、画像だけの **タイル(簡易)** で表示できます。ホイール1目盛りで画像を1段送ります。タイルでは `Ctrl`＋ホイールで画像の大きさを変えられます。
4. 画像をダブルクリックして個別ビューワを開きます。左右キー、またはホイールを上に回して前の画像、下に回して次の画像へ移動できます。所属を判定できない画像は **所属未確定** から確認できます。

Checkpointの評価別ペインは、見出しをクリックすると開閉できます。ペインごとにスクロールでき、展開したペイン間の境界をドラッグすると高さを調整できます。

**アプリの設定** の配色は **ライト**、**ダーク**、**システムに合わせる** から選べます。**画像キャッシュを作る** の初期値はオフです。オンにすると一覧用の縮小画像を保存します。オフに戻すと、このアプリの設定で作成した画像キャッシュを削除します。

画像をごみ箱に送ったときや、プロジェクト間の振り分け・Checkpoint廃棄で画像を移動したときは、元のパスに対応するキャッシュを取り除きます。キャッシュの整理に失敗した場合は別途お知らせします。

Archive化と解除では、作成済みの画像キャッシュを移動先に引き継ぎます。キャッシュがまだない画像は、次に表示したときに作成します。

## 画像を整理する

- 画像一覧の右クリックから、ごみ箱への移動、移動先プロジェクトの選択、代表サムネイルの設定ができます。`Ctrl` や `Shift` で複数選択できます。個別ビューワでは `Delete` キーで表示中の画像をごみ箱へ送れます。所属未確定の画像が含まれるときは、対象枚数と元の保存パスを確認できます。
- **プロジェクトへ移動** では、移動先のプロジェクトと参照ルートを指定します。画像のファイル名と一意に一致するCheckpointのArchiveへ移動します。所属未確定の画像や複数画像にも使えます。候補がない、または複数ある画像は元の場所に残ります。代表サムネイルは選んだ元画像からJPEGを生成し、Checkpointと同じフォルダーに保存します。
- 別のドライブやネットワーク共有にまたがる参照ルートを設定するときは、保存前に確認が出ます。画像を実際にコピーして移動する場合も実行前に確認し、コピーの完了を確認してから元画像を削除します。
- プロジェクト間のラベル重複は、Outputが重なる範囲で判定します。旧版の保留が残り、候補が現在のプロジェクトで一意の場合は、所属を確認してから右クリックの **旧版の保留を解除…** で再照合できます。
- プロジェクト設定の **サムネイル** タブにある **サムネイル一括登録** で、保存済みの設定に基づいて未設定分をまとめて登録できます。Archiveを優先し、相対パス順で最初に読み込める画像を使います。登録済みのサムネイルはそのまま残ります。
- プロジェクト設定の **アーカイブ設定** で、前日までのOutput画像をCheckpoint別に **Archive実行** し、**Archiveを開く** からエクスプローラーで成果物を取り出せます。**Archiveを戻す** では、Archive化した画像のうちArchiveに残っているものを元のOutputへ戻します。Checkpointを複数選択し、右クリックの **アーカイブ化**・**アーカイブ化解除** から対象を絞ることもできます。起動時の自動実行は既定でオフで、解除を実行するとオフになります。
- Archiveを元に戻すための移動記録はポータブル版の `data/archive-history` に保存します。展開先を移す場合は、同じ `data` にある `settings.json` と合わせて引き継いでください。
- Archive化や解除で空になった移動元フォルダーは自動で削除します。参照ルートと、他のファイルが残るフォルダーは保持します。
- 評価の変更とCheckpoint廃棄を使うには、連携対応版のHandpickerSuiteを起動し、生成された評価JSONを指定します。Checkpointを目的の評価の見出しや一覧へドラッグするか、一覧の右クリックから評価を変更できます。折りたたんだ評価も見出しで受け付けます。廃棄は `delete` 評価を付けてから右クリックで実行します。対象の画像生成を停止してから実行すると、画像をArchiveへ退避し、Checkpoint本体をごみ箱へ送ります。
- Suiteの連携対応版へ切り替える際は、旧版のSuiteと古い削除スクリプトを終了し、連携対応版が出力するスクリプトを使ってください。

## アプリの更新

署名付きの配布版は起動時にGitHub Releasesを確認します。手動で確認する場合は **アプリの更新を確認** を選んでください。起動時の確認は **アプリの設定** で切り替えられます。承認後、画像や評価の処理が終わるまで待ち、新版が正常に起動することを確認します。

展開先の `HandpickerStudio.exe` を起動してください。本体は `app/versions`、設定とArchiveの復帰用記録は `data`、既定の画像キャッシュは展開先直下の `cache` に保存します。従来版の展開先で起動窓口を置き換える場合は旧版を終了し、旧版のZIPと設定・Archiveの復帰用記録を別の場所に控えてから展開してください。

起動窓口の差し替えが中断され、展開先のEXEを起動できない場合は、Studioのプロセスを終了してから `app/update/previous-launcher.exe` または更新作業フォルダー内の `launcher-backup.exe` のうち、最後に正常に使えた版の控えを展開先直下に `HandpickerStudio.exe` として復元してください。手元に控えがなければ、公式配布ZIPの起動窓口と本体を利用できます。復旧の際も `data` と `cache` は保存先に残してください。

## 評価を別のPCへ移す

プロジェクト設定の **評価の移行** タブから、そのプロジェクトの評価を `Anima_20261125_153000.json` のようなファイル名で書き出せます。移行先のStudioでは対象プロジェクトを選び、同じタブのインポートからファイルを開きます。ファイル名とバイト数が一意に一致するCheckpointに適用し、既存評価を変更する場合は件数を確認します。Suiteでは **Checkpoint Tag Export / Import** の **Import File…** で同じJSONのファイル名を指定します。

**エクスポートに廃棄したCheckpointの履歴を含める** を選ぶと、Studioで廃棄したCheckpointを `delete` 評価として引き継げます。チェックを外した場合は、現在あるCheckpointの評価だけを書き出します。Studio同士の取り込みでは、JSONに含まれる履歴を既存の履歴に追加します。

## 配布ZIPのビルド

アプリアイコンを組み込む場合は、ビルド前に `HandpickerStudio/HandpickerStudio/Assets/HandpickerStudio.ico` にICOファイルを置きます。

.NET 10 SDKを導入したWindows環境で、リポジトリのルートからPowerShellで実行します。

```powershell
.\build.ps1
```

`artifacts/HandpickerStudio-<version>-win-x64.zip` が生成されます。ビルドは実行ごとの作業フォルダで行い、検証済みのZIPを成果物ディレクトリに配置します。

更新試験と正式配布に使う署名付きのZIPは、[自動アップデート詳細設計](spec/HandpickerStudio_AutoUpdate.md#3-ビルドと署名鍵) の配布モードで生成します。
